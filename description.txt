BMS PROJECT

The project is about creating a web interface hosted on a raspberry pi that contrls a fleet of arduino mkr controllers in order to controll heaters inside the house.
It should also manage multiple howseholds. Each house is composed of multiple rooms with each room having a controller + ruuvi-tag sensor pair assigned to it.
Each room can have set multiple programs that start on different times and specify different temperature targets.

The structure of the project should be as follows:

1. The Arduino mkr 1010 wifi controler:
    - reads temperature from a ruuvi-tag temperature sensor via bluetooth
    - toggels on/off the heater output that set on pin 6 on the board
    - once per minute requests from an API hosted on the raspbarry pi that gives the controller the folowing data and overwrite the default config via the route /get_state:
        a. the current target temperature (default 23 celsius)
        b. the negative_delta that, if the current temperature is lower then target - delta the heater is switched on (default 0.1 celsius)
        c. the positive_delta that, if the current is higher then target + delta the heater is switched off (default 0.1 celsius)
        d. the MAC address of the associated ruuvi sensor
    - the controller should be configurable via the serial monitor as follows and retain the configuration even after it is turned off:
        a. set the ssid and password of the local wifi
        b. set the api route by ip or by alias eg: BMS on port 2026
        c. set default MAC address for the associated ruuvi sensor
        d. reset configuration if the controler recives the text "reset" via serial with the arduino app

2. The raspberry pi 4 model B:
    - should host the following 2 aplications:
        i. the web API on port 2026 that exposes the following routes:
            a. GET /get_state responds with the current state of the requesting controller, controller id is determined my its fix ip address
            b. PUT /set_config?id="household_id" that sets the new config for the specified home, if the household_id does not exist add it to the list of houses 
            c. GET /get_config?id="howsehold_id" get the config of a house
            d. GET /get_house_list returns list of existing houses
        
        ii. A react frontend in order to configure the sistem by comunicating with the above mentiond API. The frontend should have the following features:
            a. add a new house th the system
            b. select a house and view each room with it's associated configuration
            c. add/remove rooms from a house
            d. eddit the room's programs by adding or removing them
            e. eddit a room's associated controler ip address and temperature sensor MAC address
    - it is also needed a script that installs all the needed frameworks/apps on the raspbery pi + 2 .desktop files that lounch the 2 servers on login
